## 1. 验证方法

### 1.1 判定口径

| 指标 | 含义 |
| --- | --- |
| `pages` | 提取文本中的分页符数量 + 1 |
| `chars` | 提取出的非空白字符总数 |
| `cjk` | 汉字字符占 `chars` 的比例 |
| `verdict` | `EXTRACTABLE` / `SCANNED?` / `EMPTY` |

判定规则（先判空、再判扫描件）：

```
chars < 500                    → EMPTY      （提取不出内容）
cjk / chars < 30%              → SCANNED?   （提取出内容但几乎无汉字 = 扫描件/图片型）
否则                           → EXTRACTABLE（电子文本，可直接进 RAG）
```

| 工具 | 版本/路径 |
| --- | --- |
| 提取器 | `pdftotext -enc UTF-8 -layout`（`C:\texlive\2024\bin\windows\pdftotext.exe`） |
| 统计脚本 | `docs/_work/verify_pdf.py`、`verify_pdf2.py`、`finalize.py` |
| Python | `C:\Python312\python.exe` |

> ⚠️ **本机注意事项**：`python` 命令命中的是 Microsoft Store 的 stub（非交互环境下返回 exit 9009），必须用绝对路径 `C:\Python312\python.exe`。

## 4. 一个曾经错误的结论（已纠正）

> ⚠️ **本节结论已修正。原文称「太保团体终身重疾 E 款里没有出现"等待期"这三个字」，这是错的。**

### 4.1 错在哪

原文结论来自抽取脚本 `harvest()` 的一个缺陷：该函数只取关键词的**首次出现**位置，并在其后 200 字符内要求匹配到「数字 + 期限」格式。重疾 E 款里「等待期」首次出现在**目录页**，那一行是：

> `90 日内本公司承担的责任有所不同，请注意………………………………………2.3`

后面跟的是页码 `2.3`，不匹配期限格式，于是函数返回 `null`，脚本把它报告成「该 PDF 可能不含此主题」。

**这是判据本身的样本覆盖缺陷造成的假阴性**，不是文档事实。

### 4.2 实际情况

「等待期」一词在重疾 E 款中确实出现，且定义条款在正文：

| 位置 | 原文 |
| --- | --- |
| 条款目录 p1 | `90 日内本公司承担的责任有所不同，请注意…………` |
| **正文 2.3.1 p4** | 「若被保险人在本合同生效或最后一次复效（以较迟者为准）之日后 **90 日（90 日为等待期，下同）**内因意外伤害以外的原因导致身故……」 |
| 正文 p9（被保险人增加） | 「新增被保险人 **90 日的等待期**自其保险责任开始或本合同最后一次复效（以较迟者为准）之日起计算」 |

修订后的定位脚本（`clean_and_threshold.py`）在 6 个关键条款上全部命中：
`2.3 等待期`、`2.4 免赔额`、`2.7 责任免除`、`1.4 犹豫期`、`2.4 责任免除`、`2.3.1 身故保险金（内含 90 日等待期定义）`。

### 4.3 修正后的通用教训

1. **判据返回「未找到」时，先怀疑判据，别急着下结论。** 假阴性会直接变成错误的事实断言，再被下游文档引用、放大。
2. **「未找到」要细分为 `NOT_FOUND` 与 `FORMAT_MISMATCH`**——前者是内容不存在，后者是样本没覆盖到。本次事件属于后者。
3. **定位条款要按编号，不要按关键词。** 关键词会命中「提及」而非「定义」：按「犹豫期」抓，取到的是「5.2 减保 投保人可在犹豫期后申请减保」，而不是 1.4 犹豫期的定义。
4. **必须区分目录条目与正文条款。** 条款 PDF 的目录里也写着「2.3 等待期」，取第一个匹配会拿到目录行。判据：正文标题后紧跟大段文字，目录项后面是下一个目录项。

### 4.4 但由此引出的真问题（仍然成立）

即便「等待期」一词存在，**重疾 E 款里没有一节标题就叫「等待期」**——它是作为括注写在 2.3.1 身故保险金里的（`90 日为等待期，下同`）。这个事实带来的真实困难见下一节：问「重疾险等待期」时，检索会稳定地偏向医疗险那一节。
