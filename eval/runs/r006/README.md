# ⚠️ r006 是一轮**作废**的评测，不要用于任何对比

## 为什么作废

这一轮跑的时候，评测脚本 `run_iteration.py` 的 delta 解析与后端不同步：

- 后端 `ChatService#sendDelta` 把 delta 用 **JSON 字符串**承载
- 前端 `App.jsx` 有 `JSON.parse(payload)`，显示正常
- **评测脚本没有**，原样拼接

于是同一份响应在页面上显示正常，在评测里变成

```
"除""另""有""约""外""，""自""本合同""生效之日起"" 3""0"" 日内""（""含""第"" 3""0"" 日""）""为""等待""期""。"
```

每个字被逐字 JSON 转义，数字被劈成 `3" "0`——**答案本身就是坏的**。

## 后果

| 指标 | r006（作废） | 真实量级 |
| --- | --- | --- |
| 应答类命中率 | **3/42 = 7%** | 与 r005 同量级（约 38%） |
| 引用命中 | 12/34 | — |

应答类暴跌 38% → 7% **完全由这个解析 bug 造成**，与检索、切割、参数无关。

## 为什么会被忽略

它**不报任何错**。每条用例都正常返回了 HTTP 200，答案字段也有内容，
只是内容被转义污染了。指标看起来「像一个真实但很差的结果」——
如果不是逐条去看答案，几乎不可能发现。

这也是留这份记录的理由：数据本身没有异常标记，只有结论会被误信。

## 正确做法

- 用 **r007**（修复后重跑）作为有效轮次
- 复现与验证：`python eval/run_iteration.py --tag r007`
- 修复位置见 `eval/run_iteration.py` 顶部的 2026-10-13 补记

> 对应的**检索侧 trace 不受影响**——`trace_stages.py` 走的是
> Dify 的只检索 API，不经过 SSE 通道，所以 t001 的 trace 结论仍然有效。
